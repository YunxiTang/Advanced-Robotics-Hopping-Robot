# 凸 MPC（Convex MPC）控制器设计方案

平面双足机器人 `hopper.xml` 的控制器升级方案：用单刚体模型（SRBD）上的凸 MPC
优化地面反力，再经 `J^T` 映射到关节力矩，替换掉现有的 Raibert 三回路控制器。

对标 MIT Cheetah 的 `Dynamic Locomotion in the MIT Cheetah 3 Through Convex
Model-Predictive Control`（Di Carlo et al., IROS 2018）。

---

## 1. 为什么 Raibert 控制器不够用

下面四条都是在本仓库当前模型上实测到的，不是推测。

| 问题 | 实测证据 |
|---|---|
| **三个回路的解耦假设不成立** | Raibert 假设 SLIP 点质量 + 轻腿。实际躯干俯仰惯量 `I_yy = 0.0269 kg·m²`，飞行相摆腿的角动量反作用把躯干甩出去，耦合系数实测 **0.56**（把腿质量从人体比例 32% 降到 18% 后才降到 0.30）。躯干因此长期保持 **−0.44 rad** 的平均后仰，落脚点对速度彻底失去权威。 |
| **姿态回路的增益被数值稳定性卡死** | 姿态力矩作用在髋关节上，而髋关节自身的质量矩阵对角元只有 `≈0.004 kg·m²`（是**腿**的惯量，不是躯干的）。显式阻尼要求 `kd·dt/I < 2`，实测上限 `attitude_kd ≈ 32`。**kp 可以加，kd 不能加** —— 抬高躯干后无法按惯量同比例放大增益。 |
| **能量注入是 bang-bang 的** | `±thrust_gain·energy_error` 实测比虚拟弹簧力大一个数量级，`leg_kp_stance` 从 200 扫到 700 结果几乎不变 —— 腿刚度已经完全失效。 |
| **相位靠时间时钟** | 现有 walker 用 `(t·f) mod 1` 排相位，欠驱动系统无法与自身动力学同步。 |

**结构性结论**：这台机器是点足、无踝驱动的欠驱动双足。俯仰**只能**通过
(a) 支撑相地面反力对质心的力矩，和 (b) 落脚点位置 来控制。Raibert 的
PD 结构无法在满足摩擦锥的前提下最优地分配这两者，而 MPC 正好可以。

## 3. 可控性预算（先确认这条路走得通）

在动手前先验证 MPC 有足够的俯仰权威，否则白做。

**单支撑**（一只脚着地，`r ≈ (0, −0.38)`）：

```
τ_pitch = r_x·f_z − r_z·f_x = 0.38·f_x
|f_x| ≤ μ·f_z = 0.8 × 13.0 = 10.4 N
⇒ |τ_pitch| ≤ 3.95 N·m  ⇒  α = 3.95 / 0.0269 ≈ 147 rad/s²
```

**双支撑**（两脚间距 `Δx ≈ 0.16 m`，靠垂直力差分产生力矩）：

```
τ_pitch = Δx · Δf_z / 2 ≈ 0.16 × 13.0 / 2 ≈ 1.04 N·m（仅重新分配体重）
若允许 f_z ∈ [0, 50] N，权威显著更大
```

147 rad/s² 的俯仰角加速度对 2.5 Hz 步频（周期 0.4 s）是充裕的。
**结论：方案可行**，且 `duty = 0.65`（30% 双支撑）应当保留，双支撑期是
俯仰权威最强的窗口。

## 4. 总体架构

```
                    ┌──────────────────────────────┐
   期望速度 v_des → │  步态调度器 (gait scheduler)  │ → 接触时序 c_i(k)
                    │  + 落脚点规划 (Raibert/CP)    │ → 落脚点 p_foot,i
                    └──────────────┬───────────────┘
                                   │
         质心状态 x ────────────────┤
                                   ▼
                    ┌──────────────────────────────┐
                    │   凸 MPC（SRBD，N 步预测）     │
                    │   QP: 优化地面反力 f_i(k)      │
                    │   约束: 摩擦锥 + 接触时序      │
                    └──────────────┬───────────────┘
                                   │ f_i（仅取第一步）
                    ┌──────────────┴───────────────┐
                    ▼                              ▼
        ┌───────────────────────┐    ┌──────────────────────────┐
        │ 支撑腿: τ = −J_i^T f_i │    │ 摆动腿: IK + 关节空间 PD  │
        └───────────────────────┘    └──────────────────────────┘
                    └──────────────┬───────────────┘
                                   ▼
                              data.ctrl[4]
```

**关键点**：姿态 PD 被**整个删掉**。俯仰由 MPC 通过在两只支撑脚之间分配
地面反力来控制，这正是当前控制器做不到的事。

## 5. 简化模型：平面单刚体（SRBD）

状态（7 维，最后一维是常数 1，用来把重力写成线性项）：

```
x = [ p_x, p_z, θ, v_x, v_z, ω, 1 ]ᵀ
```

控制（每只脚 2 维力，共 4 维）：

```
u = [ f_lx, f_lz, f_rx, f_rz ]ᵀ
```

连续时间动力学（足端位置 `r_i = p_foot,i − p_com` 视为已知，由步态调度器给出
—— 这是使问题**保持凸性**的关键近似）：

```
ṗ_x = v_x
ṗ_z = v_z
θ̇   = ω
v̇_x = (1/M) Σ_i f_ix
v̇_z = (1/M) Σ_i f_iz − g
ω̇   = (1/I) Σ_i ( r_ix·f_iz − r_iz·f_ix )
```

矩阵形式 `ẋ = A_c x + B_c u`：

```
A_c[0,3] = 1      A_c[1,4] = 1      A_c[2,5] = 1      A_c[4,6] = −g

对第 i 只脚（列 2i, 2i+1）：
B_c[3, 2i  ] = 1/M
B_c[4, 2i+1] = 1/M
B_c[5, 2i  ] = −r_iz / I
B_c[5, 2i+1] = +r_ix / I
```

一阶欧拉离散（`A_c` 近似幂零，MIT Cheetah 同样这么做）：

```
A_d = I + A_c·Δt          B_d(k) = B_c(k)·Δt
```

注意 `B_d` **逐预测步不同**（`r_i` 随质心前移和换步而变），必须逐步重建。

## 6. QP 构造（凝聚式 / condensed）

把动力学代入，消掉状态变量，只留控制序列 `U ∈ R^{4N}`：

```
X = A_qp·x₀ + B_qp·U

A_qp = [A_d; A_d²; …; A_d^N]                        (7N × 7)
B_qp[k, j] = A_d^{k−j−1}·B_d(j)   (j ≤ k)，否则 0    (7N × 4N)
```

目标函数：

```
min  Σ_{k=1}^{N} ‖x_k − x_ref,k‖²_Q  +  Σ_{k=0}^{N−1} ‖u_k‖²_R
```

整理成标准 QP：

```
H = 2 ( B_qpᵀ Q̄ B_qp + R̄ )
g = 2   B_qpᵀ Q̄ ( A_qp x₀ − X_ref )
min ½ Uᵀ H U + gᵀ U
```

参考轨迹（匀速前进、保持高度、躯干竖直）：

```
x_ref,k = [ p_x0 + v_des·kΔt,  z_des,  0,  v_des,  0,  0,  1 ]ᵀ
```

`p_x` 的权重取 **0** —— 我们不镇定绝对位置，只镇定速度。

## 7. 约束

每个预测步、每只脚：

```
摩擦锥（平面下就是两条线性不等式）：
    f_ix − μ·f_iz ≤ 0
   −f_ix − μ·f_iz ≤ 0

单边性 + 上限（摆动腿用 f_z^max = 0 强制置零）：
    0 ≤ f_iz ≤ f_z^max·c_i(k)
```

其中 `c_i(k) ∈ {0,1}` 是步态调度器给出的接触时序。**接触时序是外生的**
—— 这正是问题保持凸性（而不是 MINLP）的原因。

规模：`N=20, 4 控制量 → 80 个决策变量`，`8N = 160` 条不等式。
osqp 在这个规模上是微秒级，完全可以每个控制周期重解。

## 8. 地面反力 → 关节力矩（`J^T` 映射）

**符号约定必须推导清楚，弄反了机器人会直接原地爆炸。**

设 `f` 为地面作用在机器人上的反力（GRF），`J = ∂p_foot/∂q_leg`（世界系，
基座固定）。腿作用在**环境**上的力是 `F_env = −f`，虚功原理给出：

```
τ = Jᵀ F_env = −Jᵀ f
```

**用现有代码交叉验证**（防止符号错误）：取腿竖直向下、基座固定，
`p_foot = (0, −l(q_knee))`，则 `J_knee = (0, −dl/dq)`。
设 GRF 为 `f = (0, +F)`（把身体往上推），于是

```
τ_knee = J_kneeᵀ·(−f) = (0, −dl/dq)·(0, −F) = (dl/dq)·F
```

这与现有 `controller.py` 中 `tau_knee = dl_dq * f_radial` **完全一致**
（`f_radial > 0` 表示沿腿把髋推离足端）。✅ 符号确认。

实现上用 MuJoCo 的 `mj_jac` 取足端几何体的雅可比，取 x/z 两行、该腿两个
关节自由度对应的两列，得到 2×2 的 `J_i`。

## 9. 步态调度与落脚点规划

沿用现有的时钟调度（`step_freq = 2.5 Hz`, `duty = 0.65`），但落脚点改为
Raibert / capture-point 启发式：

```
p_foot,i = p_hip,i  +  v·T_stance/2  +  k_v·(v − v_des)
```

对 MPC 而言，预测时域内的 `r_i(k)` 按下式给出：

```
r_i(k) = p_foot,i(planned) − ( p_com,0 + v_des·kΔt )
```

即：当前已着地的脚用**实际足端位置**，时域内才落地的脚用**规划落脚点**，
并扣掉质心的前移。

---

## 10. 摆动腿控制

MPC 不管摆动腿。摆动腿继续用已经写好的方案：足端轨迹（抬腿高度
`swing_clearance`，正弦抬升）→ 2 连杆逆运动学 → 关节空间 PD。

注意 `swing_knee_kd` 必须小（小腿质量矩阵对角元 `≈8e-4 kg·m²`，
`kd·dt/I < 2` ⇒ `kd < 3.2`）。这个坑前面已经踩过一次。

## 13. 验证计划（每步都要有验收标准）

分阶段验证，**每一阶段不过就不进入下一阶段** —— 前面在盲目调参上已经
浪费了太多时间。

1. **QP 离线自检**：固定站立位形，接触时序全 1，检查解出的
   `f_lz + f_rz ≈ Mg = 13.0 N`，`f_x ≈ 0`。不过则模型或符号有错。
2. **`J^T` 映射自检**：把上一步的 GRF 映射成力矩，在 MuJoCo 里施加，
   验证机器人能**静止站立** ≥ 5 s，质心漂移 < 1 cm。
   这一步单独验证了第 8 节的符号推导。
3. **原地踏步**：`v_des = 0`，跑 10 s。验收：不摔、`|pitch| < 0.15 rad`、
   质心高度波动 < 3 cm。
4. **定速行走**：`v_des = 0.5 m/s`，跑 30 s。验收：速度稳态误差 < 15%、
   `|pitch|max < 0.25 rad`、无摔倒。
5. **速度跟踪**：`v_des` 在 0.3 → 0.8 m/s 间阶跃，验证跟踪与恢复。
6. **抗扰**：在质心施加水平脉冲（如 5 N·0.1 s），验证能恢复。

每一阶段都记录指标到 `doc/` 下，便于和 Raibert 基线对比。

## 14. 已知风险与回退

| 风险 | 缓解 / 回退 |
|---|---|
| `r_i` 用规划值而非真实值，模型失配 | 时域缩短到 N=10；或每步用实际足端位置重建 `B_d` |
| 一阶欧拉离散在 `dt=0.02` 下误差偏大 | 改用 `scipy.linalg.expm` 做精确离散化 |
| QP 偶发不可行（摩擦锥 + 时序冲突） | 把 `f_z` 上下界做成软约束（加松弛变量 + 大权重） |
| 单支撑期俯仰权威不足（仅 147 rad/s²） | 提高 `duty` 增加双支撑占比；或降低步频 |
| MPC 频率跟不上（Python 里 osqp 调用开销） | 每 40 个仿真步解一次，中间零阶保持；必要时用 `osqp.update()` 热启动而非重建 |

## 16. 实现记录：与本设计的差异（as-built）

本节由实现阶段补充，记录代码与上面设计方案的差异，以及每一条差异背后的
实测依据。设计正文保持原样未改。

代码位置：`mujoco_sim/mpc.py`（`SRBDParams` / `ConvexMPC`）、
`mujoco_sim/controller.py`（`MPCGaitParams` / `MPCWalkController`）、
`mujoco_sim/validate_mpc.py`（第 13 节的验收测试）。
验收结果：`doc/mpc_validation.md`（6/6 全部通过）。

### 16.1 参数差异

| 项 | 设计 | 实现 | 依据 |
|---|---|---|---|
| 俯仰惯量 `I` | 0.02686 | **0.0145** | 见 16.2 |
| `step_freq` | 2.5 Hz | **4.0 Hz** | 见 16.3 |
| `Q` 俯仰权重 | 250 | **500** | 0.5 m/s 下 30 s 实测，p95 俯仰 0.250 → 0.226 rad，其余指标无代价；900 会摔 |
| `f_z` 下界 | 0 | **接触时 3 N** | 见 16.4 |
| `r_i(k)` 中的质心预测 | `v_des` | **实测 `v`** | 速度误差 0.5 m/s 时，按 `v_des` 预测会让时域内每个力臂偏差最多 0.2 m —— 比力臂本身还大 |
| 设定值积分 | 无 | **速度 + 高度积分修正** | 见 16.5 |

摆动腿阻尼增益也从 walker 的 `(3.0, 2.0)` 降到 `(1.0, 0.5)`，见 16.6。

### 16.2 俯仰惯量：整机刚体值高估了一倍

全机绕质心 `I_yy = 0.02686`，但其中只有 **0.01136 属于躯干**，其余 58%
在两条腿上。腿是力矩控制的，地面反力把躯干俯仰起来时腿并不跟着刚性转动。
用恒定 GRF 经 `-Jᵀf` 驱动模型、测 `d(torso_pitch)/dt`，实测等效惯量
**0.012–0.016**。

这一条不是精度问题而是成败问题：用 0.02686 时 MPC 认为每牛顿只能买到实际
一半的俯仰响应，俯仰回路等于 2 倍增益，机器人**连站都站不住**（1 s 内摔
倒）；换成 0.0145，同一份代码站立 5 s 漂移 6 mm。

第 3 节的可控性预算据此要重算：单支撑 `α = 3.95/0.0145 ≈ 272 rad/s²`，
比原估计更宽裕，结论（方案可行）不变。

### 16.3 步频 2.5 → 4.0 Hz

步幅是 `v·duty/step_freq`，所以步频越高、每一步落脚点离质心越近，支撑脚
产生的干扰力矩 `r_x·f_z`（MPC 要花摩擦锥去抵消的那个量）按比例变小，摆动
腿对躯干的反作用也一起变小；同时落脚点修正速度的带宽翻倍。25 s 实测
（平均速度 / p95 俯仰）：

| `v_des` | 2.5 Hz | 3.5 Hz | 4.0 Hz |
|---|---|---|---|
| 0.3 | 0.29 / 0.09 | 0.29 / 0.04 | 0.29 / 0.05 |
| 0.5 | 0.49 / 0.22 | 0.50 / 0.08 | 0.50 / 0.06 |
| 0.7 | 摔倒 | 0.71 / 0.16 | 0.69 / 0.12 |
| 0.8 | 摔倒 | 0.80 / 0.26 | 0.79 / 0.14 |

即第 14 节风险表里"单支撑期俯仰权威不足"的缓解手段，实测**降低步频是错的
方向，应当提高步频**。`duty` 仍保留 0.65。

### 16.4 `f_z` 需要正的下界

只给 `f_z ≥ 0` 时，QP 会发现一个漏洞：与其花力气抵消偏心支撑脚的俯仰力矩，
不如把**所有脚都卸载**、腾空几个预测步——在代价函数里这更便宜。落到实机上
就是 `τ = -Jᵀ0 = 0`，腿彻底软掉、脚脱离地面，一个周期内步态崩溃。给接触脚
加 3 N 下界（MIT Cheetah 对 9 kg 机器人用 10 N，按体重比例相当）即可禁止。

### 16.5 设定值积分：SRBD 的力亏损是**稳态**的

SRBD 忽略的东西——腿占 18% 质量和 58% 俯仰惯量、接触是柔性的、`τ = -Jᵀf`
只对"无质量腿 + 刚性接触"精确——合起来表现为**机器人要得到却拿不到的力**，
而且是稳态的。纯比例控制器对稳态扰动只能用稳态误差来回答：实测前进速度卡
在 `k_v·v_des/(T_st/2 + k_v)`（约目标的一半），质心高度低 2 cm。

处理方式是对控制器**瞄准的设定值**做积分修正（而不是直接加力），QP 结构
完全不动，且同一个速度修正量同时作用于 MPC 的速度参考和 Raibert 落脚点
偏移这两条通道。高度修正需要 0.12 m 的行程：0.5 m/s 下 0.05 m 限幅仍低
19 mm，而此时支撑腿只有 0.27 m 长（最大可达 0.334 m），说明限制它升高的
不是运动学而正是这份力亏损。

### 16.6 摆动腿阻尼：`kd·dt/I < 2` 这条经验法则是错的

代码里原有的判据只看质量矩阵对角元。两自由度腿的正确判据是
`dt·M⁻¹·diag(kd)` 的**特征值**全部落在 (0,2) 内，而腿的逆质量矩阵严重非
对角：

```
M⁻¹[leg] = [[  862, -1009],
            [-1009,  2838]]
```

交叉项和对角元同量级，髋与膝的阻尼互相破坏稳定性。walker 的 `(3.0, 2.0)`
对应特征值 `(0.61, 3.52)`——每个时间步放大 2.52 倍，实测膝力矩在第一只脚
离地后 8 ms 内走完 1.7、-2.9、7.4、-15.7、36、-79、150、饱和。改成
`(1.0, 0.5)` 后特征值 `(0.19, 0.95)`，两个模态都收敛。刚度 kp 离各自的上
限还很远（`dt²·eig(M⁻¹kp) < 4` 允许到 ~9000），**缺的只有阻尼**。

### 16.7 摆动腿必须在躯干系下给定，不能在世界系

按世界系方向保持摆动腿（即逆运动学里带 `- torso_pitch` 项）会形成**正
反馈**：`M⁻¹[pitch, hip] = -168`，`-kp·θ` 的髋力矩给出
`θ̈ = +168·kp·θ`，kp = 60 时发散速率 100 rad/s。实测第一只脚离地瞬间髋力
矩即走 -192、+141、-111、+102 N·m，半秒内躯干仰翻。改为在躯干系下给定
（去掉该项）即可根除这条通路；代价是躯干俯仰 0.15 rad 时落脚点偏差
`l·sin(pitch)` ≈ 4 cm，而把俯仰压到远小于此正是 MPC 自己的职责。

### 16.8 支撑腿的保持项要用任务空间

支撑脚在世界系里静止，而腿关节以约 1 rad/s 扫过——所以关节空间的
`-kd·q̇` 项正好是在给"把身体带向前"的那个运动踩刹车。改成对**足端世界速度**
的虚拟阻尼后，脚踩实时两项都为零（目标就是脚当前位置、足端速度为零），
MPC 保有全部权限；只有脚离开落脚点时才起作用。

### 16.9 第 13 节验收的两处说明

- **第 2 阶段（`Jᵀ` 映射自检）必须在分腿站姿下做**。两脚落在同一 x 上时，
  这台点足机器人在矢状面内就是"单点支撑的倒立摆"：没有踝关节，水平地面
  反力只能连同它绕该点的力矩一起产生，质心在脚正上方的平衡点是**真正不可
  控的**——不靠迈步谁也稳不住（实测 5 s 漂移 0.54 m）。分腿站姿有 0.16 m
  支撑多边形，可以靠两脚垂直力差分造出自由俯仰力矩，也就是第 3 节预算的那
  份权威。**站立是双支撑问题，行走不是。**
- **第 4 阶段的俯仰验收取 p95 而非 max**：最大值是每次触地的瞬态尖峰。
  实测 0.5 m/s、30 s：p95 = 0.056 rad，max = 0.083 rad，两者都远在
  0.25 rad 以内。

### 16.10 两条 Raibert 基线已删除（推翻第 11 节）

第 11 节要求保留 `--gait hop|walk` 作为对照，实现阶段**按用户要求删掉了**
`RaibertController` 和 `WalkingController`，`--gait` 选项一并取消，MPC 成为
唯一控制器。

删除的理由是它们本来就不能用：在当前的**双足**模型上，`hop` 稳态质心高度
7.9 m（把自己发射出去），`walk` 发散到 MuJoCo 报
`Nan, Inf or huge value in QACC` 并自动重置状态。用引入 MPC 之前的启动路径
复现得到同样结果，即与本次工作无关。它们的控制律是为**单腿** SLIP 模型写的，
模型换成双足后从未重新整定，因此作为"对照基线"没有意义。

落脚点规划里的 Raibert / capture-point 启发式（第 9 节）保留——那是一条
标准的落脚点公式，和被删掉的那两个控制器无关。

顺带修掉了这件事暴露出的一个隐患：MuJoCo 检测到发散会**把仿真状态重置**，
`data.time` 因此归零，`while data.time < duration` 的循环**永不退出**（跑
发散的控制器就会挂死）。`sim.py` 的主循环现在同时按步数封顶，并在发生重置时
明确告警而不是静默吞掉。

### 16.11 其它文件层面的变动

- 模型文件 `hopper.xml` → **`biped.xml`**（`<mujoco model="planar_biped">`）：
  它早已不是单腿跳跃机，文件名会误导人。
- 关键帧 `home` → **`split_stand`**，只服务于第 2 阶段的 `Jᵀ` 自检；步态从
  对称的 `mpc_stand` 起步。
- 新增控制台入口 `biped`（`pyproject.toml` 的 `[project.scripts]`），
  一行启动：`uv run biped --view`。macOS 下 `--view` 会自动把进程 re-exec
  到同目录的 `mjpython`，用户不需要知道这件事。

## 17. 扩展到三维（as-built）

第 5–16 节是平面（矢状面）版本的设计与实现记录，本节记录把机器人和控制器
推广到三维时的改动与实测。平面版本的全部经验（16.2–16.8）在三维下依然成立，
下文只写新增的部分。验收结果见 `mpc_validation.md`（9 个阶段全部通过）。

### 17.1 模型

- 躯干由 `slide_x / slide_z / torso_pitch` 三个自由度改为 **free joint**
  （六个浮动自由度，全部无驱动）。`qpos = (x, y, z, qw, qx, qy, qz, …)`，
  free joint 的角速度在**本体系**下，控制器转到世界系再喂给 SRBD。
- 每条腿增加一个 **髋滚转（hip_roll，绕躯干 x 轴）**，与髋俯仰共用一个转动
  中心（2 自由度万向髋）。这样摆动腿逆运动学仍是闭式解：滚转决定腿所在的
  平面，平面内就是原来的等腰两连杆。执行器 4 → 6 个，`data.ctrl` 顺序为
  `(hip_roll_l, hip_l, knee_l, hip_roll_r, hip_r, knee_r)`。
- **没有髋偏航关节，也不需要**：点足不能抵抗绕竖直轴的转动，支撑腿在脚上
  自由转动，偏航力矩完全由 `r × f` 产生。
- 质量分布不变（总质量 1.30 kg）。行走质心高度由 0.408 m 降到 **0.36 m**
  （见 17.4）；`mpc_stand` 关键帧相应改为蹲姿，`split_stand` 删除——三维下
  两个点足的支撑多边形是一条线段，任何脚位下机器人都是绕这条线的倒立摆，
  不迈步就站不住，"原地站立"这一验收无从谈起。

### 17.2 MPC：13 维 SRBD

采用 Cheetah 3 原文的三维形式：

    x = [φ, θ, ψ, p, ω, v, 1] ∈ R^13,   u = [f_l, f_r] ∈ R^6
    Θ̇ = Rz(ψ)ᵀ ω,   ṗ = v,   ω̇ = I_w⁻¹ Σ r_i × f_i,   v̇ = Σ f_i / m − g e_z

- 两个近似与原文一致：小滚转/俯仰（欧拉角速率映射退化为偏航旋转），忽略
  陀螺项 `ω × Iω`。
- `Rz(ψ)` 取**每个预测步的参考偏航**，因此转弯时动力学时变但仍是线性的；
  凝聚时 A_k 随 k 变化，改用递推 `row_k = A_k row_{k−1} + [… B_k …]`。
- 摩擦锥改为**内接于 MuJoCo 椭圆锥的四棱锥**，`μ_mpc = μ/√2`，每脚每步 5 行
  约束。规模 120 个决策变量、200 行约束，单次求解约 1.7 ms（预算 20 ms）。
- 有效惯量 `diag(0.0145, 0.0145, 0.003)`：俯仰沿用 16.2 实测值，滚转按同样
  规则（躯干本身 0.011），偏航取躯干 0.002 与整机 0.004 之间。
- 权重：滚转与俯仰同为 500，**偏航只有 150**（见 17.5）。

### 17.3 控制器

- 速度指令在**航向系**下给出：`(前进, 向左)`，外加转向角速度。参考轨迹中的
  速度随参考航向逐步旋转，要求机器人走的是圆弧，而不是方向缓慢变化的直线。
- 落脚点：Raibert 公式推广到二维（x、y 各一条，增益 `k_v = k_vy = 0.12`），
  髋位置与反馈都在触地时刻的预测航向下表达；名义步宽 0.05 m，略窄于髋距
  0.068 m——点足单支撑时质心横向偏离支撑点多少，就要侧向倒多少。
- 支撑腿：`τ = −Jᵀf`（3×3，**取接触点**的雅可比，17.4），加关节阻尼前馈
  和任务空间的保脚项。
- 摆动腿：闭式三关节 IK + 关节 PD，在**参考航向系**下解算（17.4）。
- 设定值积分：前进、横向速度和高度三路。航向设定值积分转向指令，但只把
  限幅（±0.3 rad）后的值交给 MPC（17.4）。

### 17.4 实现中发现的问题（每一条都是用数字而不是看图找到的）

1. **摆动腿的偏航正反馈**（16.7 的偏航版）。没有关节绕竖直轴转，看上去摆动
   IK 用实测偏航无妨；其实不然：躯干偏航 ψ 时，两侧髋点各前后移动
   `0.068·ψ`，世界系下固定的摆动目标相对髋点随之移动，髋的响应又把躯干往同
   方向拧。实测 0.5 m/s 下 4 s 偏航 1 rad，随后摔倒。改为以**航向设定值**
   和名义髋位置解算 IK 后，实测姿态不再进入摆动腿的关节目标。
2. **限幅要加在 MPC 看到的量上，而不是设定值本身。** 最初把航向设定值夹在
   实测偏航 ±0.3 rad 内，一旦误差超限，设定值就被拖着走，丢掉的航向再也
   找不回来（0.6 m/s 下偏离 1.4 rad 后摔倒）。现在设定值只积分指令，限幅只
   作用于交给 MPC 的参考。
3. **关节阻尼偷走地面反力。** 模型给每个腿关节加了少量粘性阻尼（髋 0.2）。
   支撑腿关节以 1–3 rad/s 扫过，每个髋力矩中最多约 0.6 N·m 耗在阻尼上，
   折算到脚端有好几牛——而体重才 13 N。结果是下沉（高度积分项停在
   +4.6 cm）、触地迟到（0.5 m/s 时 16% 的计划支撑时间脚还在空中）、弹跳
   （13% 的时间双脚离地）。把阻尼力矩前馈抵消后降到 4% / 2%，滚转幅度减半，
   0.08 rad 的稳态俯仰偏置消失。
4. **`−Jᵀf` 必须取接触点而不是足球心。** 地面作用在球心下方一个足半径
   （2.8 cm）处，而小腿在转动。躯干固定时实测：球心雅可比给出的水平力少
   11%，接触点雅可比误差 0.03 N。固定躯干本身也踩了两次坑：weld 约束太软，
   14 N 推力把骨盆顶起 8 cm；每步重置基座状态也不够，步内腿仍会加速基座，
   通过质量矩阵等效于给腿加了重力（f_z 偏大 0.6–0.7 N）。最终做法是把躯干
   质量和惯量放大 10⁶ 倍再加每步重置——这就是第 2 阶段验收。
5. **速度上限由膝关节行程决定。** 在 0.408 m 的质心高度下，三维步态跑起来后
   支撑腿在扫程两端伸直到膝关节限位（0.337 m），载荷改走关节限位约束而不是
   控制器，腿变成撑杆，机器人被"撑杆跳"甩出去。实测（5 s 爬升到目标速度后
   保持到 20 s，表中为摔倒时刻）：

   | z_des | 0.6 m/s | 0.7 m/s | 0.8 m/s |
   |---|---|---|---|
   | 0.408 | 7.4 s | 6.2 s | 6.1 s |
   | 0.39 | ok | 8.9 s | 6.9 s |
   | 0.38 | ok | 17.6 s | 5.3 s |
   | 0.36 | ok | ok | 11.0 s |
   | 0.35 | ok | ok | 8.8 s |

   取 0.36 m，上限由 0.5 m/s 提到 **0.7 m/s**。0.8 m/s 能走 5–15 s，然后被
   绊倒（0.1 s 内偏航跳约 1 rad）；平面版本能到 0.8 m/s，是因为它不会滚转、
   偏航或横摆，脚也不会侧向擦地。

### 17.5 偏航为什么只能轻权重

每条摆动腿偏离中线 0.068 m，前摆时带着绕竖直轴的角动量；同一时刻另一侧的
支撑腿相对躯干向后扫，贡献同号的角动量。躯干自身偏航惯量只有
0.002 kg·m²，于是每一步都反向扭转约 ±0.1 rad——这正是人靠摆臂抵消的那个
运动。它是内力、均值为零，硬顶它只会浪费摩擦锥：实测 0.5 m/s 下偏航权重由
150 提到 600 或 2000 都会摔倒，降到 50 则无影响。把躯干偏航惯量人为放大
3–6 倍也救不了 0.6 m/s 以上的步态——那时的瓶颈是 17.4 的第 3、5 条，不是
偏航。

### 17.6 验收计划的改动

第 13 节的 6 个阶段在三维下保留并加了 3 个，全部带数值标准：

| 阶段 | 内容 | 与平面版的区别 |
|---|---|---|
| 1 | QP 自检 | 力与**三维**力矩平衡 |
| 2 | `Jᵀ` 映射 | 固定躯干，直接读 MuJoCo 接触力，误差 < 2%（原为分腿站立 5 s） |
| 3 | 原地踏步 | 加水平漂移 < 0.3 m |
| 4 | 0.5 m/s 稳态行走 30 s | 滚转与俯仰 p95 均 < 0.15 rad，航向漂移 < 0.3 rad |
| 5 | 速度阶跃 | 0.3 → **0.7** → 0.3 m/s（原为 0.8，见 17.4 第 5 条） |
| 6 | 前向推扰 | 不变 |
| 7 | **侧向推扰** | 新增 |
| 8 | **横移** 0.2 m/s | 新增 |
| 9 | **边走边转** 0.3 m/s、0.5 rad/s | 新增 |

`uv run python -m mujoco_sim.validate_mpc --jobs 8 --write` 约 35 s 跑完全部阶段。

## 18. 踝关节与平足（as-built）

本节记录给机器人加上**踝关节和平足**后的改动。第 16、17 节的经验全部仍然
成立，下文只写新增的部分。验收结果见 `mpc_validation.md`：10 个阶段全部
通过，比 17.6 多出"原地站立"一项。

### 18.1 模型

- **2 自由度踝**：先俯仰（`ankle_pitch`，轴 `0 -1 0`），再绕俯仰后的 x 轴
  滚转（`ankle_roll`），两轴交于踝点。踝点就是原来点足球心的位置，脚底在
  踝点下方 `ANKLE_H = 0.028 m`（原来的足半径）。因此腿长、行走高度、
  `mpc_stand` 的髋膝角都不变，踝俯仰取 `−(hip + knee)` 使脚底水平。
- **平足**：脚底 10 × 5 cm，接触用脚底四角的四个小球（半径 4 mm，
  condim 3），即**四个点–平面接触**，而不是盒–平面接触。四点合起来能传递
  完整的接触力旋量：压力中心（CoP）可以在四点围成的矩形内任意移动（踝后
  3.1 cm 到踝前 6.1 cm，左右各 2.1 cm），四点的摩擦还能抵抗绕竖直轴的
  扭转。盒–平面碰撞在脚底晃动时接触点数会在 1 到 4 之间跳变，所以不用。
- **同时加了髋偏航（`hip_yaw`，绕躯干 z 轴）**。这一项是平足逼出来的：点足
  不能抗扭，靠支撑脚原地打转就能转弯（17.1）；平足能抗扭，没有髋偏航时
  躯干航向就被锁死在支撑脚上，只能靠脚底打滑来转弯。三个髋轴交于一点，
  逆运动学仍是闭式的。
- 每条腿 6 个关节，执行器 6 → 12 个。`data.ctrl` 顺序为左腿
  `(hip_yaw, hip_roll, hip, knee, ankle_pitch, ankle_roll)`，然后右腿。
- 踝和髋偏航加了 `armature = 2e-4 kg·m²`（减速器的反射转子惯量）。脚只有
  20 g，绕踝惯量约 1e-5 kg·m²；按 16.6 的显式积分稳定性条件，没有 armature
  时踝的阻尼增益上限约 0.03，几乎没法控制。
- 总质量 1.30 → **1.31 kg**（脚由 15 g 的球变为 20 g 的脚板）。

### 18.2 MPC：每只脚一个接触力旋量

控制输入由每脚一个力变为每脚一个**力旋量**：

    u_i = [f_x, f_y, f_z, m_x', m_y', m_z'] ∈ R^6,   u = [u_l, u_r] ∈ R^12
    ω̇ = I_w⁻¹ Σ (r_i × f_i + Rz(ψ_i) m_i')

- 力在世界系；力矩取**脚参考点**（踝点在脚底的投影，`sole_*` site），
  表达在**脚的偏航系**（带撇号，`ψ_i` 为该脚航向）。这样写的好处是约束
  矩阵保持常量：CoP 约束在脚坐标系里是一个固定的矩形，而脚的朝向进入
  `B` 矩阵，反正 `B` 每次都要重建。已着地的脚用实测位置和航向；视界内才
  落地的脚用规划的落脚点和航向（航向设定值外推到触地时刻）。
- 每脚每步 11 行约束：摩擦四棱锥 4 行、`f_z` 上下界 1 行，外加

      ±m_x' ≤ k·Y·f_z                         （CoP 左右不出脚底）
      −k·X_front·f_z ≤ m_y' ≤ k·X_back·f_z    （CoP 前后不出脚底，m_y' = −x'·f_z）
      ±m_z' ≤ μ_t·f_z                         （扭转摩擦）

  这就是逐脚写出的 ZMP 条件。上下界随 `f_z` 线性缩放，所以平足仍然是 QP。
  `k = 0.8` 为 CoP 裕量：SRBD 的任何建模误差都会让实际力旋量偏离指令，CoP
  贴边时只要往卸载方向偏一点，脚就会翻到边上，接触退化成线，QP 指望的
  力矩也随之消失。`μ_t = 0.012 m`，约为四角摩擦能提供的扭转上限的三分之一，
  因为同样的摩擦还要承担剪切力。
- 力矩正则 `R_moment = R / (0.05 m)² = 0.4`：力矩的代价等于在 5 cm 力臂上
  产生它的那个力的代价。若直接用 `R`，力矩（量级约 0.1 N·m）几乎是免费的。
- 规模：240 个决策变量、440 行约束。
- **求解器由 OSQP 换成 DAQP**（稠密有效集法），见 18.4 第 1 条。单次求解
  约 7 ms（预算 20 ms）。

### 18.3 控制器

- **支撑腿**：`τ = −Jᵀw`，`J` 是**脚参考点处**的 6×6 雅可比（平移 + 转动），
  六关节腿的 `J` 是方阵，所以任意接触力旋量都能实现。QP 给的力矩先从脚
  偏航系转回世界系。加上关节阻尼前馈（17.4 第 3 条，现在覆盖全部 6 个
  关节）和 6 维任务空间保脚项。保脚项的转动部分把脚底拉回水平（目标航向
  为脚当前航向或规划航向）；脚平贴地面时误差和角速度都为零，不影响 MPC。
- **摆动腿**：闭式 6 关节 IK。髋偏航 = 脚的目标航向 − 航向设定值；髋滚转、
  髋俯仰、膝在髋偏航后的坐标系里放置**踝点**，解法与点足相同；两个踝关节
  使脚底相对参考躯干水平：`ankle_pitch = −(hip + knee)`，
  `ankle_roll = −hip_roll`。整个 IK 仍然不含任何实测姿态（16.7、17.4 第 1 条）。
  代价是躯干俯仰 0.07 rad 时，脚会以 0.07 rad 先着脚跟或脚尖，由支撑侧
  保脚项的转动部分在触地后压平。摆动过程中脚的航向由离地航向线性插值到
  规划航向。
- **落脚航向**取航向设定值外推到触地时刻，而不是实测偏航：躯干每步反向
  扭转约 ±0.1 rad（17.5），按实测航向落脚会走出外八、内八交替的"之"字。
  差值由髋偏航吸收。
- **姿态设定值积分**（18.4 第 3 条）：与速度、高度积分同样的结构，作用于
  MPC 的滚转/俯仰参考，`ki_att = 0.5`，限幅 ±0.1 rad。
- **原地站立**：`duty = 1` 使两只脚在整个周期里都是支撑脚，同一个控制器，
  只是步态时钟不再抬脚（`uv run biped --stand`）。

### 18.4 实现中发现的问题

1. **接触力矩让 QP 的条件数坏到 ADMM 不收敛。** 两只脚可以用许多几乎等价的
   方式在力矩和载荷之间互换，只有很轻的正则能区分它们，Hessian 条件数约
   2×10⁶。OSQP 中位 1275 次迭代（约 70 ms，预算的 3.5 倍），部分求解撞到
   4000 次上限；把力矩变量缩放成力的量纲只能减半。有效集法不在乎条件数：
   DAQP 精确求解同样的问题约 7 ms，没有容差要调。（缩放对 DAQP 没有影响，
   已删除。）新增依赖 `daqp`，去掉 `osqp` 和 `scipy`。
2. **扭矩能精确传递，前提是关节阻尼前馈。** 躯干固定时，`−Jᵀw` 的力和
   倾覆力矩误差都在 1% 以内，但绕竖直轴的扭矩少了 25–33%。原因是 MuJoCo 的
   软摩擦在持续扭矩下允许脚以 0.05 rad/s 缓慢蠕动，髋偏航 0.2 的阻尼吃掉
   0.01 N·m。这是 17.4 第 3 条在新关节上的重演。行走控制器本来就有阻尼前馈，
   第 2 阶段验收现在走同一条代码路径：力误差 0.004 N，力矩误差 6×10⁻⁵ N·m。
3. **姿态也需要设定值积分。** 原地踏步时躯干稳态后仰 0.057 rad（点足版本
   也有，0.026 rad），0.5 m/s 时后仰 0.013 rad，0.7 m/s 时前倾 0.012 rad。
   这是 SRBD 没建模的力矩，而且随速度变化，固定偏置消不掉。逐项排除过：去掉
   保脚项转动部分、改 `R_moment`、改 CoP 裕量都只差几毫弧度。对 MPC 的滚转/
   俯仰参考加限幅积分后三种速度的均值都小于 0.001 rad，踏步俯仰 p95 由
   0.088 降到 0.022 rad；`ki_att` 在 0.5–2.0 之间表现相同。
4. **速度上限没有变，仍为 0.7 m/s。** 0.8 m/s 能站住 30 s，但只走到
   0.72 m/s，俯仰 p95 0.16 rad；0.9 m/s 约 10 s 后摔倒。上限由膝关节行程
   决定（17.4 第 5 条），腿长没变，平足帮不上忙。（跑步步态把上限提到
   1.25 m/s，见第 19 节。）

### 18.5 验收计划的改动

| 阶段 | 内容 | 与 17.6 的区别 |
|---|---|---|
| 1 | QP 自检 | 双支撑时两脚航向不同；新增**单支撑**：质心在脚底上方但偏离参考点，只能靠接触力矩平衡。单支撑时水平力放宽到 2% Mg，因为正则化使精确解不是最优解（把力倾斜零点几牛，借 0.36 m 的高度产生一部分力矩，比踝更便宜），净力矩仍为零 |

| 3 | **原地站立 10 s** | 新增：5 s 时 2 N 侧推 100 ms，漂移 < 2 cm，滚转/俯仰 < 0.05 rad。点足无法完成 |

## 19. 跑步步态（as-built）

本节记录**跑步**步态。第 16–18 节全部仍然成立。验收结果见
`mpc_validation.md`：12 个阶段全部通过，比 18.5 多出"跑步"和
"走–跑–走切换"两项。

### 19.1 跑步就是占空比小于 1/2

步态时钟不变（4 Hz，两腿相差半个周期），每只脚在每个周期里支撑 `duty`
的时间：

- **走**：`duty = 0.65`，始终至少一只脚着地，每周期两次双支撑；
- **跑**：`duty = 0.35`，每周期两次**腾空**（两脚都离地），名义腾空比例
  `1 − 2 × 0.35 = 30%`，每次约 26 ms。

MPC、SRBD、约束、`−Jᵀw` 全部不变。腾空只是接触序列里一段没有脚着地的
区间：这些步上所有输入被约束为零，状态只受重力，QP 在 0.4 s 的视界里
看得到下一次腾空，自然会在支撑期里规划出越过它所需的蹬地冲量。不需要
为腾空期单独写控制律。

跑步的支撑时间更短，支撑脚在髋下扫过的距离 `v·duty/f` 也短了约一半，
所以膝关节行程（17.4 第 5 条）不再是 0.7 m/s 处的瓶颈。

### 19.2 步态选择与切换

- `gait = "walk" | "run" | "auto"`（命令行 `--gait`）。`auto` 为默认：
  指令速度（`hypot(Vs, Vy)`）超过 `run_above = 0.7 m/s` 时跑，回落到
  `0.7 − 0.1 = 0.6 m/s` 以下再走（滞回）。
- 选定 0.7 而不是更高：强制走到 0.75 m/s 虽然速度跟得上，但滚转 p95
  0.09 rad、质心起伏 12 cm，已经很难看；0.8 m/s 在 19 s 时摔倒。
- **占空比按 0.5 /s 的速率渐变**，不是瞬间切换。瞬间把 0.65 改成 0.35，
  相位在 0.35–0.65 之间的腿会从支撑直接变成摆动的中途，摆动目标跳变。
  渐变时一次切换约两个步幅，摆动轨迹连续。
- 站立（`duty = 1`）不受步态选择影响。

### 19.3 实现中发现的问题：计划支撑 ≠ 已经着地

步态时钟是开环的：到了支撑相，不管脚是否着地都开始支撑。走路时脚最多
差几毫米，问题不明显；跑步腾空之后，脚可能还在空中几厘米。此时 MPC 给
这只脚分配的力旋量没有地面可推，`−Jᵀf` 作用在不受载的腿上只会把腿甩到
完全伸直（实测膝关节越过了限位），机器人落在一根"撑杆"上被弹起（17.4
第 5 条的另一种触发方式）。

修正（`MPCGaitParams.late_touchdown_speed`）：

1. 计划支撑开始时记 `landed = False`；在计划支撑期内测到任一脚底接触后置
   `True` 并锁存到本次支撑结束。
2. 未着地的脚继续用摆动控制器，沿规划落脚点以 0.5 m/s 向下探，最深到地面
   以下 5 cm（IK 会把膝裁剪到限位内）。
3. MPC 视界第 0 步把这只脚的接触标志置 0（当前不指望它出力），后续步仍按
   计划支撑；**着地瞬间立即重解 QP**，不用等 20 ms 的 MPC 周期。
4. 保脚项的目标改为这次摆动瞄准的落脚点（原来是下一个周期的落脚点，脚被
   弹离地面时会伸向错误的位置）。

效果：1.0 m/s 跑步（从静止直接起跑）质心起伏 8.4 → 2.0 cm，俯仰 p95
0.080 → 0.036 rad；1.2 m/s 从只能跑到 1.12 m/s、起伏 15 cm 变为
1.20 m/s、起伏 2 cm。走路也受益：0.5 m/s 俯仰 p95 0.040 → 0.021 rad，
滚转 0.015 → 0.008 rad。

### 19.4 速度上限

斜坡加速 4 s，保持 30 s：

| 目标 | 走 | 跑 |
|---|---|---|
| 0.5 m/s | 0.50，俯仰 p95 0.02 | 0.50，0.01 |
| 0.7 m/s | 0.70，0.03 | — |
| 1.0 m/s | — | 1.00，0.04 |
| 1.25 m/s | — | 1.25，0.06 |
| 1.3 m/s | — | 7 s 摔倒 |

跑步的上限不在落脚精度：1.4 m/s 时摆动脚仍落在规划点 2 cm 以内。限制
是躯干往上"爬"：超过 1.25 m/s 后质心比目标高出 5–10 cm，支撑腿在蹬地
结束前就伸直，机器人被撑起、翻倒，仍是 17.4 第 5 条。试过提高步频
（5 Hz）、改占空比（0.3、0.4）、降低质心（0.34 m）、改 Raibert 增益、
平滑摆动轨迹（smoothstep 与 ease-out，两者在 1.2 m/s 反而摔倒），
1.4 m/s 全部摔倒。

（以上是手臂还没有关节时的数字。加上摆臂之后上限变为走 1.3 m/s、跑
1.7 m/s，见 20.3。）

| 阶段 | 内容 |
|---|---|
| 11 | **跑步** 1.0 m/s，20 s：速度误差 < 10%，实测腾空比例（由 MuJoCo 接触列表得到，不是计划值）> 名义值的 80%，姿态 p95 < 0.15 rad，航向漂移 < 0.3 rad |
| 12 | **走 → 跑 → 走**，指令 0.5 → 1.0 → 0.5 m/s，`auto` 步态：三个保持段速度误差 < 10%，走的段腾空 < 2%，跑的段腾空 > 20% |

## 20. 手臂与摆臂（as-built）

本节记录给手臂加上关节、让它在行走和跑步中摆动。第 16–19 节全部仍然
成立；验收仍是 12 个阶段，全部通过。

### 20.1 模型

- 每条手臂 3 个关节：**肩俯仰**（绕 −y，正值手向前）、**肩滚转**（两侧
  都是正值外展，右臂轴取反）、**肘**（绕 −y，正值屈肘）。各配一个力矩
  电机，±5 N m，关节带 2×10⁻⁴ kg m² 的电枢惯量（与踝关节同理）。
- 每条手臂 0.05 kg（上臂 0.03，前臂加手 0.02），从躯干盒子里扣除，
  **总质量仍为 1.31 kg**，SRBD 参数不变。
- 手臂的 body 写在两条腿之后：MuJoCo 按树的顺序给 qpos、qvel 和执行器
  编号，所以腿的全部索引不变，手臂的 6 个量接在后面（`data.ctrl[12:18]`）。

### 20.2 摆臂控制律

MPC 不知道手臂的存在。手臂由一个独立的关节 PD 控制
（`MPCWalkController._arm_torques`）：

    theta_i  = hip_i + knee_i / 2              （髋到踝连线相对躯干的角度，实测）
    q_sp,l*  = clip(k · (theta_r − theta_l) / 2, ±0.6)      左臂随右腿
    q_sp,r*  = clip(k · (theta_l − theta_r) / 2, ±0.6)      右臂随左腿
    q_sr*    = 0.12 rad                        （手离开大腿）
    q_el*    = 0.5 + s · (1.3 − 0.5),  s = (0.65 − duty) / (0.65 − 0.35)

`k = arm_swing_gain = 1.5`，目标经过 20 ms 一阶低通。因为跟随的是腿的
**实际**角度，摆幅随步长自动变化，原地踏步时几乎不摆，不需要单独的速度
调度：0.5 m/s 走约 ±10°，1.0 m/s 跑约 ±12°。肘角随占空比渐变，所以走跑
切换时手臂也连续地弯曲。

为什么这对 MPC 是"好的"扰动：两臂反相，俯仰反力矩互相抵消；它们绕竖直
轴的角动量与摆动腿相反，正好抵消 17.4 第 11 条说的、MPC 不该用摩擦锥去
对抗的那部分偏航扰动。

| | 走的上限 | 跑的上限 | 0.5 m/s 走：偏航抖动 p95 | 1.0 m/s 跑：滚转 / 俯仰 p95 |
|---|---|---|---|---|
| 手臂无关节（19 节） | 0.7 m/s | 1.25 m/s | — | 0.012 / 0.037 rad |
| 有关节但不摆（k = 0） | 0.9 m/s | 1.6 m/s（俯仰 p95 0.16） | 0.038 rad | 0.013 / 0.039 rad |
| **摆臂（k = 1.5）** | **1.3 m/s** | **1.7 m/s（0.09）** | **0.028 rad** | **0.009 / 0.031 rad** |

斜坡加速 4 s，保持到 20 s。1.8、1.9 m/s 的指令不摔但只能跑到
1.73、1.79 m/s，2.0 m/s 摔倒；走 1.4 m/s 摔倒。

- 手臂有关节但不摆时上限也提高了，原因没有单独分离：手臂质量现在位置
  更高、更靠外，并且挂在 PD 关节上，而不是刚性地算在躯干盒子里。
- 增益不是越大越好：`k = 3` 时走路摆幅约 ±18°，0.5 m/s 的偏航抖动反而
  升到 0.047 rad，手臂过度抵消了腿。
- 自动步态的切换点仍是 0.7 m/s：走现在能到 1.3 m/s，但跑步作为独立步态
