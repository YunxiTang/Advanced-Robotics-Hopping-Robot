# 凸 MPC（Convex MPC）控制器设计方案

平面双足机器人 `hopper.xml` 的控制器升级方案：用单刚体模型（SRBD）上的凸 MPC
优化地面反力，再经 `J^T` 映射到关节力矩，替换掉现有的 Raibert 三回路控制器。

对标 MIT Cheetah 的 `Dynamic Locomotion in the MIT Cheetah 3 Through Convex
Model-Predictive Control`（Di Carlo et al., IROS 2018）。

---

## 1. 为什么 Raibert 控制器不够用

下面四条都是在本仓库当前模型上实测到的，不是推测。

| 问题 | 实测证据 |
|---|---|
| **三个回路的解耦假设不成立** | Raibert 假设 SLIP 点质量 + 轻腿。实际躯干俯仰惯量 `I_yy = 0.0269 kg·m²`，飞行相摆腿的角动量反作用把躯干甩出去，耦合系数实测 **0.56**（把腿质量从人体比例 32% 降到 18% 后才降到 0.30）。躯干因此长期保持 **−0.44 rad** 的平均后仰，落脚点对速度彻底失去权威。 |
| **姿态回路的增益被数值稳定性卡死** | 姿态力矩作用在髋关节上，而髋关节自身的质量矩阵对角元只有 `≈0.004 kg·m²`（是**腿**的惯量，不是躯干的）。显式阻尼要求 `kd·dt/I < 2`，实测上限 `attitude_kd ≈ 32`。**kp 可以加，kd 不能加** —— 抬高躯干后无法按惯量同比例放大增益。 |
| **能量注入是 bang-bang 的** | `±thrust_gain·energy_error` 实测比虚拟弹簧力大一个数量级，`leg_kp_stance` 从 200 扫到 700 结果几乎不变 —— 腿刚度已经完全失效。 |
| **相位靠时间时钟** | 现有 walker 用 `(t·f) mod 1` 排相位，欠驱动系统无法与自身动力学同步。 |

**结构性结论**：这台机器是点足、无踝驱动的欠驱动双足。俯仰**只能**通过
(a) 支撑相地面反力对质心的力矩，和 (b) 落脚点位置 来控制。Raibert 的
PD 结构无法在满足摩擦锥的前提下最优地分配这两者，而 MPC 正好可以。

## 3. 可控性预算（先确认这条路走得通）

在动手前先验证 MPC 有足够的俯仰权威，否则白做。

**单支撑**（一只脚着地，`r ≈ (0, −0.38)`）：

```
τ_pitch = r_x·f_z − r_z·f_x = 0.38·f_x
|f_x| ≤ μ·f_z = 0.8 × 13.0 = 10.4 N
⇒ |τ_pitch| ≤ 3.95 N·m  ⇒  α = 3.95 / 0.0269 ≈ 147 rad/s²
```

**双支撑**（两脚间距 `Δx ≈ 0.16 m`，靠垂直力差分产生力矩）：

```
τ_pitch = Δx · Δf_z / 2 ≈ 0.16 × 13.0 / 2 ≈ 1.04 N·m（仅重新分配体重）
若允许 f_z ∈ [0, 50] N，权威显著更大
```

147 rad/s² 的俯仰角加速度对 2.5 Hz 步频（周期 0.4 s）是充裕的。
**结论：方案可行**，且 `duty = 0.65`（30% 双支撑）应当保留，双支撑期是
俯仰权威最强的窗口。

## 4. 总体架构

```
                    ┌──────────────────────────────┐
   期望速度 v_des → │  步态调度器 (gait scheduler)  │ → 接触时序 c_i(k)
                    │  + 落脚点规划 (Raibert/CP)    │ → 落脚点 p_foot,i
                    └──────────────┬───────────────┘
                                   │
         质心状态 x ────────────────┤
                                   ▼
                    ┌──────────────────────────────┐
                    │   凸 MPC（SRBD，N 步预测）     │
                    │   QP: 优化地面反力 f_i(k)      │
                    │   约束: 摩擦锥 + 接触时序      │
                    └──────────────┬───────────────┘
                                   │ f_i（仅取第一步）
                    ┌──────────────┴───────────────┐
                    ▼                              ▼
        ┌───────────────────────┐    ┌──────────────────────────┐
        │ 支撑腿: τ = −J_i^T f_i │    │ 摆动腿: IK + 关节空间 PD  │
        └───────────────────────┘    └──────────────────────────┘
                    └──────────────┬───────────────┘
                                   ▼
                              data.ctrl[4]
```

**关键点**：姿态 PD 被**整个删掉**。俯仰由 MPC 通过在两只支撑脚之间分配
地面反力来控制，这正是当前控制器做不到的事。

## 5. 简化模型：平面单刚体（SRBD）

状态（7 维，最后一维是常数 1，用来把重力写成线性项）：

```
x = [ p_x, p_z, θ, v_x, v_z, ω, 1 ]ᵀ
```

控制（每只脚 2 维力，共 4 维）：

```
u = [ f_lx, f_lz, f_rx, f_rz ]ᵀ
```

连续时间动力学（足端位置 `r_i = p_foot,i − p_com` 视为已知，由步态调度器给出
—— 这是使问题**保持凸性**的关键近似）：

```
ṗ_x = v_x
ṗ_z = v_z
θ̇   = ω
v̇_x = (1/M) Σ_i f_ix
v̇_z = (1/M) Σ_i f_iz − g
ω̇   = (1/I) Σ_i ( r_ix·f_iz − r_iz·f_ix )
```

矩阵形式 `ẋ = A_c x + B_c u`：

```
A_c[0,3] = 1      A_c[1,4] = 1      A_c[2,5] = 1      A_c[4,6] = −g

对第 i 只脚（列 2i, 2i+1）：
B_c[3, 2i  ] = 1/M
B_c[4, 2i+1] = 1/M
B_c[5, 2i  ] = −r_iz / I
B_c[5, 2i+1] = +r_ix / I
```

一阶欧拉离散（`A_c` 近似幂零，MIT Cheetah 同样这么做）：

```
A_d = I + A_c·Δt          B_d(k) = B_c(k)·Δt
```

注意 `B_d` **逐预测步不同**（`r_i` 随质心前移和换步而变），必须逐步重建。

## 6. QP 构造（凝聚式 / condensed）

把动力学代入，消掉状态变量，只留控制序列 `U ∈ R^{4N}`：

```
X = A_qp·x₀ + B_qp·U

A_qp = [A_d; A_d²; …; A_d^N]                        (7N × 7)
B_qp[k, j] = A_d^{k−j−1}·B_d(j)   (j ≤ k)，否则 0    (7N × 4N)
```

目标函数：

```
min  Σ_{k=1}^{N} ‖x_k − x_ref,k‖²_Q  +  Σ_{k=0}^{N−1} ‖u_k‖²_R
```

整理成标准 QP：

```
H = 2 ( B_qpᵀ Q̄ B_qp + R̄ )
g = 2   B_qpᵀ Q̄ ( A_qp x₀ − X_ref )
min ½ Uᵀ H U + gᵀ U
```

参考轨迹（匀速前进、保持高度、躯干竖直）：

```
x_ref,k = [ p_x0 + v_des·kΔt,  z_des,  0,  v_des,  0,  0,  1 ]ᵀ
```

`p_x` 的权重取 **0** —— 我们不镇定绝对位置，只镇定速度。

## 7. 约束

每个预测步、每只脚：

```
摩擦锥（平面下就是两条线性不等式）：
    f_ix − μ·f_iz ≤ 0
   −f_ix − μ·f_iz ≤ 0

单边性 + 上限（摆动腿用 f_z^max = 0 强制置零）：
    0 ≤ f_iz ≤ f_z^max·c_i(k)
```

其中 `c_i(k) ∈ {0,1}` 是步态调度器给出的接触时序。**接触时序是外生的**
—— 这正是问题保持凸性（而不是 MINLP）的原因。

规模：`N=20, 4 控制量 → 80 个决策变量`，`8N = 160` 条不等式。
osqp 在这个规模上是微秒级，完全可以每个控制周期重解。

## 8. 地面反力 → 关节力矩（`J^T` 映射）

**符号约定必须推导清楚，弄反了机器人会直接原地爆炸。**

设 `f` 为地面作用在机器人上的反力（GRF），`J = ∂p_foot/∂q_leg`（世界系，
基座固定）。腿作用在**环境**上的力是 `F_env = −f`，虚功原理给出：

```
τ = Jᵀ F_env = −Jᵀ f
```

**用现有代码交叉验证**（防止符号错误）：取腿竖直向下、基座固定，
`p_foot = (0, −l(q_knee))`，则 `J_knee = (0, −dl/dq)`。
设 GRF 为 `f = (0, +F)`（把身体往上推），于是

```
τ_knee = J_kneeᵀ·(−f) = (0, −dl/dq)·(0, −F) = (dl/dq)·F
```

这与现有 `controller.py` 中 `tau_knee = dl_dq * f_radial` **完全一致**
（`f_radial > 0` 表示沿腿把髋推离足端）。✅ 符号确认。

实现上用 MuJoCo 的 `mj_jac` 取足端几何体的雅可比，取 x/z 两行、该腿两个
关节自由度对应的两列，得到 2×2 的 `J_i`。

## 9. 步态调度与落脚点规划

沿用现有的时钟调度（`step_freq = 2.5 Hz`, `duty = 0.65`），但落脚点改为
Raibert / capture-point 启发式：

```
p_foot,i = p_hip,i  +  v·T_stance/2  +  k_v·(v − v_des)
```

对 MPC 而言，预测时域内的 `r_i(k)` 按下式给出：

```
r_i(k) = p_foot,i(planned) − ( p_com,0 + v_des·kΔt )
```

即：当前已着地的脚用**实际足端位置**，时域内才落地的脚用**规划落脚点**，
并扣掉质心的前移。

---

## 10. 摆动腿控制

MPC 不管摆动腿。摆动腿继续用已经写好的方案：足端轨迹（抬腿高度
`swing_clearance`，正弦抬升）→ 2 连杆逆运动学 → 关节空间 PD。

注意 `swing_knee_kd` 必须小（小腿质量矩阵对角元 `≈8e-4 kg·m²`，
`kd·dt/I < 2` ⇒ `kd < 3.2`）。这个坑前面已经踩过一次。

## 11. 代码结构

```
mujoco_sim/
  mpc.py              新增
    SRBDParams        模型/权重/时域参数
    ConvexMPC
      .build(x0, contact_schedule, foot_positions, x_ref) -> (H, g, A, l, u)
      .solve() -> f[4]      仅返回第一步（滚动时域）
  controller.py       新增 MPCWalkController
    - 步态时钟 + 落脚点规划
    - 调 ConvexMPC 拿 GRF
    - 支撑腿 τ = −Jᵀf；摆动腿 IK + PD
  sim.py
    - --gait mpc 分支；把 model/data 传给控制器以取雅可比
```

保留 `RaibertController` 和 `WalkingController` 作为对照基线，不删除
（`--gait hop|walk|mpc`）。

## 12. 参数初值

| 参数 | 初值 | 理由 |
|---|---|---|
| `dt_mpc` | 0.02 s | 40 个仿真步一次；20–50 Hz 是常规 MPC 频率 |
| `N` | 20 | 时域 0.4 s = 恰好一个完整步态周期 |
| `Q` | `diag(0, 120, 250, 20, 5, 8, 0)` | 俯仰权重最高（欠驱动方向）；`p_x` 权重为 0 |
| `R` | `1e-3·I₄` | 轻正则，主要为了 QP 良态 |
| `f_z^max` | 50 N | ≈ 3.8·Mg，留出蹬地余量 |
| `μ` | 0.8 | 与模型 `friction` 一致 |
| `k_v`（落脚点） | 0.12 | 沿用当前 walker 的值 |

## 13. 验证计划（每步都要有验收标准）

分阶段验证，**每一阶段不过就不进入下一阶段** —— 前面在盲目调参上已经
浪费了太多时间。

1. **QP 离线自检**：固定站立位形，接触时序全 1，检查解出的
   `f_lz + f_rz ≈ Mg = 13.0 N`，`f_x ≈ 0`。不过则模型或符号有错。
2. **`J^T` 映射自检**：把上一步的 GRF 映射成力矩，在 MuJoCo 里施加，
   验证机器人能**静止站立** ≥ 5 s，质心漂移 < 1 cm。
   这一步单独验证了第 8 节的符号推导。
3. **原地踏步**：`v_des = 0`，跑 10 s。验收：不摔、`|pitch| < 0.15 rad`、
   质心高度波动 < 3 cm。
4. **定速行走**：`v_des = 0.5 m/s`，跑 30 s。验收：速度稳态误差 < 15%、
   `|pitch|max < 0.25 rad`、无摔倒。
5. **速度跟踪**：`v_des` 在 0.3 → 0.8 m/s 间阶跃，验证跟踪与恢复。
6. **抗扰**：在质心施加水平脉冲（如 5 N·0.1 s），验证能恢复。

每一阶段都记录指标到 `doc/` 下，便于和 Raibert 基线对比。

## 14. 已知风险与回退

| 风险 | 缓解 / 回退 |
|---|---|
| `r_i` 用规划值而非真实值，模型失配 | 时域缩短到 N=10；或每步用实际足端位置重建 `B_d` |
| 一阶欧拉离散在 `dt=0.02` 下误差偏大 | 改用 `scipy.linalg.expm` 做精确离散化 |
| QP 偶发不可行（摩擦锥 + 时序冲突） | 把 `f_z` 上下界做成软约束（加松弛变量 + 大权重） |
| 单支撑期俯仰权威不足（仅 147 rad/s²） | 提高 `duty` 增加双支撑占比；或降低步频 |
| MPC 频率跟不上（Python 里 osqp 调用开销） | 每 40 个仿真步解一次，中间零阶保持；必要时用 `osqp.update()` 热启动而非重建 |

## 15. 与 MATLAB 原版的关系

原 MATLAB 代码（`Main.m` / `Stance_Controller.m`）是单腿 SLIP + Raibert
三回路，与本方案已无对应关系。本方案**不再以复现 MATLAB 为目标**
（用户已明确放宽这一约束），而是把它作为基线对照保留。
